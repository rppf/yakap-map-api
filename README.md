# yakap-map-api

The API of YAKAP Map — accredited PhilHealth YAKAP facilities, served from a Cloudflare Worker.

## Stack

- **Hono** — HTTP API (routes under `src/routes/`)
- **Cloudflare Workers** — serverless runtime (`wrangler`)
- **Neon** — serverless PostgreSQL (queried over Neon's serverless HTTP driver via `kysely-neon`)
- **ZenStack v3** — schema + access policies (`zenstack/schema.zmodel`); Kysely-based ORM, no Prisma runtime

## Directory layout

```
zenstack/schema.zmodel   # Source of truth for the API's view of the data model (edit this)
zenstack/{schema,models,input}.ts  # Generated by `pnpm generate` — committed, do not edit by hand
src/
  index.ts               # Worker entrypoint
  app.ts                 # Hono app: middleware, route mounting, AppType export
  lib/db.ts              # ZenStackClient + kysely-neon NeonDialect (Neon HTTP) + PolicyPlugin
  middleware/            # CORS, error handler
  routes/health.ts       # GET /health
  routes/facilities/     # GET /api/facilities, GET /api/facilities/:id
```

## Setup

The Neon database and facility data are managed outside this repo — no migrations or
seeding are run here. The zmodel is aligned to the existing table via introspection.

```bash
pnpm install
cp .env.example .env               # fill in your Neon DATABASE_URL (used by `zen db pull`)
cp .dev.vars.example .dev.vars     # same DATABASE_URL (used by wrangler dev)
pnpm generate                      # zenstack generate (zenstack/*.ts)
pnpm dev                           # http://localhost:8787
```

## Previews

Preview URLs (`preview_urls = true` in `wrangler.jsonc`) let you test a live build
without touching production traffic:

- `pnpm preview` — uploads a version and prints a one-off URL:
  `<version-id>-yakap-map-api.<subdomain>.workers.dev`
- `pnpm preview:alias` — uploads a version bound to the stable alias:
  `staging-yakap-map-api.<subdomain>.workers.dev` (always points to the latest
  staging upload; any alias works, e.g. `--preview-alias my-feature`)

Notes:

- Previews reuse the Worker's secrets, so they hit the **same production Neon
  database**. Fine for this read-only API — don't use previews to test writes.
- Preview URLs are **public** by default. They can be restricted with Cloudflare
  Access (dashboard → Worker → Settings → Domains & Routes).
- Logs/tail are **not** available for preview URLs — debug locally with `pnpm dev`
  if something misbehaves only in preview.

## Endpoints

- `GET /health`
- `GET /api/facilities` — query params: `bbox=minLng,minLat,maxLng,maxLat` (Mapbox bounds order), `q` (name/street/municipality), `region`, `area`, `limit` (default 50, max 200), `offset`. Returns `{ data, meta: { total, limit, offset } }`.
- `GET /api/facilities/:id`

Backed by the existing `health_facilities` table in Neon. The PostGIS `coordinates`
column is not queryable by the ORM (`Unsupported` type) — geo filtering uses the plain
`longitude`/`latitude` columns. `id` is a BigInt in the DB and is serialized as a
number in responses.

## Workflow notes

- **Schema changes**: the Neon table is the source of truth. After changing it, run
  `pnpm exec zenstack db pull` (experimental — it rewrites `zenstack/schema.zmodel` in
  place, so review the git diff and re-apply the `policy` plugin block, the `@@allow`
  rule, and any `@map`/`@db.*` tweaks), then `pnpm generate`.
- **Reads** go through the ZenStack ORM client with the policy plugin
  (`@@allow('read', true)`; writes are denied).
- For production secrets: `wrangler secret put DATABASE_URL` (don't commit real credentials).
- The web app (`yakap-map-web`) can consume the typed API via `hono/client` with the exported `AppType` from `src/app.ts`.
